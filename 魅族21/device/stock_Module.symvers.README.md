# stock_Module.symvers — 来源说明（魅族 21）

**本文件不是从魅族 21 自己的镜像里抽出来的，而是复用 21 Pro 的。**

## 为什么可以复用

`stock_Module.symvers` 唯一用途是给「门禁 2/3 — KMI 审计 + krcrc CRC 锁定」
提供「符号 → 原厂 CRC」基准。这份基准只要满足「符号集合与 CRC 与目标机一致」
就等价，不需要来自同一台机器。

我自己实测的两个设备的 KMI 交叉核对（脚本
`crosscheck_m21_manifest.py`，输入是两个 `module_kmi_manifest.txt`）：

```
meizu21    NEED 4180 / 内核需提供 3036
21 Pro     NEED 4183 / 内核需提供 3036

共同 NEED 符号        : 4180
其中 CRC 不一致       : 0
内核需提供的 3036 个符号 CRC 100% 相同 : 3036 / 3036
meizu21 独有          : 0 个
21 Pro 独有           : 3 个
```

也就是说：**门禁实际要比对的那 3036 个符号，两个机型逐位一致。**
21 Pro 那 3 个独有符号不会出现在 21 的模块里，多出来不影响比对。

## 为什么不从 21 的 Image 里抽

原厂 `Module.symvers` 只随魅族构建树提供，不在 ROM 里。
从 `Image` 的 `__ksymtab` / `__kcrctab` 反推需要精确匹配厂商的
PREL32 相对偏移布局，两次尝试（锚点向前扫描 / 全镜像扫描）都未命中，
说明 6.1 GKI 的表布局与代码假设不同。与其继续逆向，不如用已验证等价的
数据——风险更低、结论可审计。

## 如果以后拿到 21 自己的 Module.symvers

直接替换本文件即可，门禁逻辑不变。替换后请重跑一次 CI，确认
`patch_crc_report.txt` 里「回读校验」无失败。
